# Highloader

Локальное приложение для нагрузочного тестирования HTTP API: Go запускает нагрузку и хранит историю, React показывает настройки, ход теста и отчёты. Для работы готового Windows-приложения не нужны Node.js и Go.


## Запуск готовой сборки

Запустите `dist\highloader.exe`. Приложение открывает браузер и слушает только `127.0.0.1` на свободном порту. Если браузер открыть не удалось, появится окно с адресом. Повторный запуск открывает уже работающий экземпляр. Закрытие вкладки не останавливает тест; для завершения приложения используется действие «Выйти». Для обновления сначала завершите старую версию через «Выйти», затем запустите новую: обновление вкладки не заменяет встроенные в работающий EXE файлы интерфейса.

Рабочие данные находятся в `%LOCALAPPDATA%\Highloader`: настройки — `config.json`, история — каталог `history`, журнал — `logs\highloader.log`. Параметр `--data-dir <каталог>` выбирает другой каталог данных, `--no-browser` отключает автоматическое открытие браузера.

## Подготовка запросов

Выберите папку с `.json` или `.jsonc`. Читаются только файлы непосредственно в ней. Вложенные папки пропускаются. Ошибочный файл остаётся в таблице с объяснением и не может быть выбран. Исходное тело доступно только для просмотра; имя файла сохраняется для истории и не задаёт поведение запроса.

Отметьте один файл, несколько или все допустимые. Задайте общий URL, HTTP-метод, авторизацию и заголовки. Метод и политика повторов могут иметь частные настройки для каждого шаблона. Поддерживаются готовый Bearer/JWT, Basic, API Key в заголовке или query-параметре, а также отсутствие авторизации. Токен нужно вставить готовым: приложение не получает и не обновляет его.

В файле лежит тело запроса. Оба расширения поддерживают UTF-8/BOM, комментарии и завершающие запятые JSONC. Повторяющиеся ключи объекта отклоняются. Чтобы задать заголовки с наивысшим приоритетом, добавьте перед телом единственную директиву:

```jsonc
/* @highloader {"headers":{"X-Test-Case":"example","Authorization":null}} */
{
  "requestId": "{{sys.uuid}}",
  "createdAt": "{{sys.time.iso}}",
  "quantity": "{{sys.random.int(1,5)}}",
}
```

Метаданные и комментарии не отправляются. Значение заголовка `null` удаляет его без возврата к нижнему слою. Приоритет: сгенерированные значения → общие заголовки UI → частные заголовки UI → заголовки файла. Строки файла заблокированы. Имена сравниваются без учёта регистра; дубли внутри одного слоя — ошибка. По умолчанию добавляется `Content-Type: application/json`, его также можно удалить. Фрейминг запроса, включая `Content-Length`, определяет транспорт по фактическому телу.

Примеры: [обычные шаблоны](examples/templates), [виртуальный пользователь](examples/closed), [описание примеров](examples/README.md).

## Системные значения

| Токен | Результат |
| --- | --- |
| `{{sys.uuid}}` | Новый UUID v4 логического запроса |
| `{{sys.time.iso}}` | Время UTC с миллисекундами |
| `{{sys.time.unix_s}}`, `{{sys.time.unix_ms}}` | То же время в секундах или миллисекундах Unix |
| `{{sys.request.seq}}` | Номер логического запроса, начиная с 1 |
| `{{sys.run.id}}` | Идентификатор запуска |
| `{{sys.user.id}}` | Номер пользователя, только в закрытой модели |
| `{{sys.random.int(min,max)}}` | Равномерное целое, обе границы включены |
| `{{sys.random.choice(array)}}` | Равномерный выбор из непустого массива JSON-скаляров |

Пример выбора строки в JSON: `"{{sys.random.choice([\"standard\",\"express\"])}}"`. Токен, занимающий всё строковое значение, сохраняет тип результата: число, boolean или null. Внутри текста результат становится частью строки. Выражения обрабатываются только в строковых значениях тела. Параметры — литералы; произвольный код не исполняется.

В исходном JSON `"\\{{sys.uuid}}"` отправит буквальный текст `{{sys.uuid}}`. Одинаковое выражение вычисляется один раз на логический запрос. Повторные попытки используют точно то же отрендеренное тело. Новый запрос получает новые UUID, случайные значения и время. Повтор запуска из истории получает новый идентификатор запуска.

## Профиль нагрузки и повторы

Открытая модель задаёт RPS независимо от скорости ответов. Если генератор не успевает, он продолжает с доступной скоростью и показывает недобор и пропущенный спрос. Пропущенный слот не считается отправленным запросом; накопленная нагрузка не выстреливает позже залпом.

Закрытая модель задаёт число виртуальных пользователей. Каждый ждёт завершения своего логического запроса, включая повторы и задержки, затем начинает следующий. При уменьшении ступени занятые лишние пользователи завершают текущую работу. Число пользователей не является обещанием определённого RPS.

Ступени имеют целую длительность в секундах и неотрицательный уровень. Их можно менять на таймлайне или числами. Ноль задаёт паузу. В открытой модели повторы могут расходовать общий RPS либо идти сверх RPS первичных запросов. На нулевой ступени первый вариант приостанавливает повторы, второй допускает их до конца отправляющей фазы профиля.

Выбор шаблона: по кругу в порядке выбранных элементов; случайно равномерно; каждый по одному в перемешанном круге; случайно с положительными весами. Столбец «Вес» виден только в последнем режиме; введённые веса сохраняются при переключении. Повторы не переключают шаблон.

Начальные настройки: POST; 100 RPS на 60 секунд; лимит 1000 незавершённых логических запросов; таймаут попытки 30 секунд; 0 повторов; общий срок запроса 120 секунд. При включении повторов доступны статусы, сетевые ошибки, таймауты, фиксированная или экспоненциальная задержка и случайный разброс. Начальная задержка — 1 секунда, максимум — 10 секунд. Общий срок включает ожидание бюджета и задержки между попытками. Частные поля политики независимо наследуют общие значения; явные `0` и `false` не означают наследование.

## Выполнение и результаты

После старта настройки зафиксированы. «Остановить» прекращает новые отправки и повторы и ждёт уже отправленные запросы в пределах их сроков. «Не дожидаться отправленных» отменяет оставшиеся клиентские операции. Уже получивший запрос сервер может продолжить его обработку. Пока ресурсы не освобождены и результат не сохранён, новый тест не начинается.

Счётчики различают логический запрос и HTTP-попытку. Последовательность `503 → 503 → 200` — один успешный логический запрос, три попытки и две HTTP-ошибки. Любой ответ вне 200–299 считается HTTP-ошибкой. Полученный HTTP-статус и ошибка чтения тела могут одновременно относиться к одной попытке; число неуспешных попыток не удваивается. Редиректы автоматически не выполняются, TLS-сертификаты проверяются.

Задержка попытки включает полное чтение ответа. Длительность логического запроса включает повторы и ожидания. Отчёт содержит min/mean/max и p50/p90/p95/p99. Отменённые и неизвестные исходы учитываются отдельно и не превращаются в нулевую задержку. Квантили объединяются через распределения; для длительности от 1 мс допустимая относительная погрешность — не более 1%, ниже этого порога используется микросекундное разрешение.

CPU — загрузка всего локального компьютера от 0 до 100%, а не только процесса Highloader и не тестируемого сервера. При недоступности счётчика остаётся пропуск с объяснением. Prometheus и удалённый мониторинг в эту версию не входят.

По умолчанию на шаблон сохраняются первые 5 успешных и 20 неуспешных образцов; тело запроса и ответа ограничивается отдельно 64 КиБ. Эти пределы меняются до старта. Усечение образца не изменяет отправляемое тело и не прекращает чтение ответа. Полные оригиналы шаблонов хранятся отдельно от образцов.

## История и автономный отчёт

История хранит исходные JSON/JSONC, старые имена файлов, выбранные элементы, настройки, профиль, результаты и образцы. Повтор создаёт новый черновик и работает даже после удаления исходных файлов. Удаление истории выполняется вручную. Сравнение двух запусков показывает различия настроек и измерений, без автоматического вердикта «лучше/хуже».

Готовые токены, пароли, API-ключи и значения заголовков сохраняются в локальной истории для повторения запуска — это согласованное поведение. В обычном просмотре они скрыты до явного раскрытия. Автономный HTML по умолчанию удаляет значения авторизации и из отображения, и из встроенных данных. Опция «Включить авторизацию в отчёт» сохраняет их явно. Это удаление известных данных авторизации, а не обещание очистки произвольных бизнес-данных тела.

Результаты сохраняются контрольными срезами примерно раз в секунду. После аварии незавершённый запуск становится прерванным: видны последний сохранённый срез и неизвестный интервал, повторная отправка автоматически не начинается. Ошибка хранения останавливает новые отправки; доступные несохранённые данные отмечаются явно.

Если «Выйти» остановилось из-за ошибки сохранения, доступный отчёт остаётся открыт для просмотра и экспорта. После освобождения запросов и записи появляется «Закрыть без сохранения»: действие требует подтверждения и теряет только несохранённый срез, сохраняя уже записанную историю.

## Сборка и проверка

Для сборки нужны Go и Node.js/npm. Версии зависимостей закреплены в go.mod и web/package-lock.json.

Выполните `powershell -File scripts/build.ps1`: скрипт устанавливает зависимости, собирает интерфейс, автономный отчёт и dist/highloader.exe. Сначала соберите интерфейс: Go использует встроенные web/dist и web/report-dist.

Проверка: `powershell -File scripts/verify.ps1 -Frontend`. Отдельно: `node web/scripts/check-report-runtime.mjs`.

## Скачать Windows-сборку

Откройте [Actions → Windows build](https://github.com/avfirsov/highloader/actions/workflows/build.yml), выберите успешный запуск ветки `main` и скачайте артефакт `highloader-windows-x64` внизу страницы. Для скачивания нужен вход в GitHub. Распакуйте ZIP и запустите `highloader.exe`; рядом находится файл контрольной суммы SHA-256. Артефакты хранятся 14 дней.

Сборка запускается при каждом push в `main`. Её также можно запустить вручную кнопкой **Run workflow** на странице Actions.
